# features/orders

Orders (P3): `OrdersPage` (every order, with the derived state and the detail: lines in EA, source documents, timeline), with system views (All, Needs review — the old Review worklist, now also at /review —, Payment hold, Pending, Archive suppressed, Historical) and "Re-check" on Review orders in the list and the detail (`sales.order.operate`), `ManualOrderPage` (Draft → Submit with the EA preview, FR-OB-19a). Built from `@/platform-ui` only. 940s, shipments and invoices join the detail in P4–P6.

Shipments & lots (2026-11-03): each 945 is a card with its ship-to (N1 ST), carrier in words, BOL, 940 ref, ISA13/GS06/ST02, received time, its source file (opens it on Documents) and "no 997 sent back" (Sales sends none for 945s), then its line items one table per pallet (LX) with a subtotal, each row matched to its order line. A split shipment's parts ("9451a", "9451b") are cards Part a, Part b. During the shadow run the lines show the 945's figures in Shipped EA and Backordered EA like applied ones (derived from the shadow 945 rows; never applied, never written to shipped_ea).

Order from a 945 (FR-OB-25c): a 945 that matched no order shows a "No order" tab on Documents (preset "945 with no order"), with the lines it would make and Create order (`OrderFrom945.tsx`). Partner and PO come from the 945's reference; without one the user chooses. Shadow run only; the order reads "Created from 945", has no prices, and Send 940 is hidden on it.

Status (PRD 9.1): the list and the order header show one Status from sales-api (`order_status`, `order_status_label`, `on_hold_reason`), the Short shipped badge and the Detail (`status_detail`, empty unless it adds something); colours and the Shopify badges are in `orderStatus.ts`, the cells in `OrderStatusCells.tsx`. Never work a status out here. The internal lines (`fulfillment_status`, `invoice_status`, `order_state`, `hold_reason`) show on Overview, under Internal status, and drive the action buttons only. The list's Shopify column shows payment, fulfilled, archived and cancelled as badges; each is filtered on its own field. The order's Overview has the Shopify section with the raw values and dates.

Stopping an order: `OrderHoldActions.tsx` shows Cancel order, Release hold or Compare the 945s from what the server says (`cancellable`, `hold_exits`), each with a required reason; `orderStatus.ts` `compare945` builds the side-by-side. `ResolveRow.tsx` resolves a 945 row matching no line: linked only to a line of the same item (`matching_lines`, from the server), else accepted with a reason. They show on a shadow order as in production and the server refuses them; `features/common/testRun.ts` sends that refusal to the status row. Nothing on an order says shadow: the Health page, the Connections setting and Shadow compare do.

Orders opens on the Open view (the first preset, from the server), unless the person has a default view. Confirm delivery and Record a return need `sales.order.operate`; invoice edit, send and release stay on `sales.invoice.manage`.
