# UniOps Finance 模块 —— 产品需求文档(PRD)与项目现状

> 版本:v1.0(2026-07-13)· 用途:供财务团队评审,核对是否符合实际业务需求
> 范围:UniOps 自建 Finance 模块 + 从用友 NC65 的历史数据迁移 + 并行期双系统协作
> 说明:本文档面向业务审核,重点是**业务需求与规则**;技术实现细节从略。带 ⚠️ 的是**需要财务确认**的点。

---

## 1. 背景与目标

公司(加拿大皇家妙克 / Canada Royal Milk)当前财务核算在**用友 NC65**(飞鹤集团共享系统,中式财务体系)里。NC65 对北美运营(加元本位、GST/HST、加拿大报表习惯)适配不佳,且是集团共享系统、灵活性受限。

**目标**:在 UniOps 里自建一套**面向北美运营、又能承接 NC65 历史与集团要求**的 Finance 模块,分三步:
1. **建立自有总账/凭证/报表内核**(不再依赖 NC 出日常账与管理报表);
2. **把 NC65 的历史财务数据完整迁入** UniOps(科目、凭证、辅助核算);
3. **切换期与集团并存**:UniOps 做日常业务,凭证按需回传 NC 供集团合并,直到 NC 退役。

**核心设计原则**:
- 底层总账**沿用 NC 的中式科目体系**(历史零重映射、与集团口径一致);北美税务(HST/GST/PST)通过**税码**表达,不改科目结构。
- UniOps 是 NC 历史数据的**忠实容器**,但不复制 NC 的中式法定处理逻辑(强制现金流量项目、金税发票等)。
- 本位币 = **加元 CAD**;支持多币种交易(USD/CNY/EUR/GBP)保留原币+本币双额+汇率。

## 3. 核心功能需求

### 3.1 总账凭证(JV / 记账凭证)—— 系统的会计脊梁
- 每一笔业务(应付计提、付款、报销、应收…)自动生成一张**记账凭证**(借贷分录)。
- **凭证生命周期**:制单(草稿)→ 审核 → 过账;并支持**弃审、反过账、红冲(红字冲销)**。
- **只有「已过账」凭证才进总账/报表**(未过账不计入余额)——这是财务的控制关口。
- 凭证含:凭证号、凭证日期、会计期间、摘要、借贷分录(科目 + 原币/本币金额 + 币种 + 汇率 + 数量核算 + 辅助核算维度)。
- 红冲:对已过账凭证生成一张**红字(负数)冲销凭证**,原凭证标记为已红冲,双方留痕(审计友好)。
⚠️ **需确认**:凭证过账流程(制单→审核→过账三步)是否符合你们现在的做法?是否需要「出纳/主管」等更多岗位?

### 3.2 科目余额表(Account Balance Report)
对齐 NC 的科目余额表,四项能力:
1. **科目余额表**:每个科目的 **期初 / 本期借方 / 本期贷方 / 期末**(本位币 CAD),按会计期间。
2. **按辅助核算展开(可勾选)**:把某个科目按它挂的辅助核算项(**部门 / 成本中心 / 收支项目** 等)展开;可任选维度组合(勾 2 个按 2 维分组、全勾全展开)。
3. **凭证钻取**:展开后任一行 → 查出由哪些凭证构成,再点进凭证/来源单据。
4. **可与 NC 对账**:导入的历史凭证纳入余额,应与 NC 的余额逐科目一致。

### 3.3 Budget Actual(预算实际)—— 供预算对比
从科目余额表按成本中心归集**实际发生额**,支撑预算 vs 实际分析。
- **业务规则(财务定稿)**:实际由 **4 个费用科目** 决定,按成本中心归类:

  | GL 科目 | 费用类别 | 归入成本中心前缀 |
  |---|---|---|
  | 5101 制造费用 | MOH(制造) | `MOH-*` |
  | 5301 研发费用 | R&D(研发) | `RD-*` |
  | 6601 销售费用 | Selling(销售) | `SELL-*` |
  | 6602 管理费用 | G&A(管理) | `GA-*` |

- **实际口径 = 期间发生借方**(不是净额——制造费用期末会结转,净额≈0)。
⚠️ **需财务重点核对**:上面 4 个科目 + 成本中心归类规则是否正确、够用?其他费用科目(如 6603 财务费用)是否也要纳入 Budget Actual?

### 3.4 应付账款(AP)与员工报销
- 现有 AP 模块:供应商发票上传、三方匹配、付款(已实现)。
- **员工报销改造(Claim Accrual,方案 B —— 待实现)**:报销在会计上也是应付(欠员工的钱)。当前只在**付款时**入账(借费用 贷银行),已批未付是**未确认的负债**。改造后:
  - **审批通过时**计提:借 费用/税 贷 **员工报销应付**(独立的「其他应付款-报销」科目,不与供应商应付混);
  - **付款时**:借 员工报销应付 贷 银行。
⚠️ **需确认**:是否要把「已批未付的报销」在账上确认为负债(权责发生制)?独立控制科目用哪个?

### 3.5 单据链 / 凭证联查(Document Chain —— 待实现)
从一张凭证或应付单能看到**完整上下游**:采购申请 → 采购订单 → 收货 → 发票 → 应付 → 凭证 → 付款,点击可钻取。目标是「看到一笔账的来龙去脉」。

## 4. NC65 历史数据迁移(需求 + 现状)

**范围**:只迁移 **加拿大皇家妙克** 这一个 NC 账簿(飞鹤集团共享库里有 17 个账簿,其余是飞鹤中国主体,不迁),**全部历史凭证**(2020–2026)。

| 迁移内容 | 规则 | 现状 |
|---|---|---|
| **会计科目(COA)** | 沿用 NC 中式科目码,导入 360 个科目;名称取英文(缺则中文) | ✅ 已导入,与 NC 一致 |
| **历史凭证** | 39,839 张凭证 / 315,048 行,按「已过账」导入,保留 NC 原凭证号 | ✅ 已导入,**逐科目余额与 NC 对账 0 差异** |
| **辅助核算维度** | 成本中心 / 部门 / 收支项目,解析并映射到 UniOps 主数据 | ✅ 三维已导入 |
| **往来档案**(供应商/客户) | 复用现有 ERP MDM 模块(已同步供应商/职员/物料;客户待加) | ⏳ 待接入 |

**关键映射规则(财务定稿,需再核对)**:
- **成本中心**:NC 成本中心(S02/E01/ENG/QA/SC/HR…)↔ UniOps 成本中心(MOH-*/RD-*/SELL-*/GA-*)是**人工整定的 1:1**。规则:**分录有成本中心码就按码归(不看部门,历史跨部门录入错误自动纠偏)、没有码就按部门归**。
- **部门**:NC 部门码(0100–0113)与 UniOps 部门码**完全一致,直接对应**。
- **收支项目**:NC(CRM 起头码,如 CRM00101 出差餐费)与 UniOps 预算科目(budget_accounts)**按 code 一一对应**。
⚠️ **需财务核对**:成本中心的整定映射表(尤其 ENG/PD/QA/SC/HR 这些汇总码的归属)是否都对?

## 5. 并行期:UniOps ↔ NC 双系统协作(设计已定,待实现)

切换后有一段**双系统并行期**:UniOps 做日常业务(应付/付款…),但**飞鹤集团合并、法定账仍在 NC**。协作方式(财务定稿):
- **UniOps 导出「应付单据」(不是凭证)** → 灌入 **NC 应付模块** → NC 审核后**按它自己的制单规则自动生成凭证**。UniOps 不替 NC 记凭证。
- UniOps 与 NC **各自生成凭证**;财务**定期复核**两边凭证是否匹配(控制点)。
- 导出方式起步 = 生成 **NC 应付模块导入文件**(按 NC 模板),财务手工引入。
- 并行期结束、NC 退役后,此流程关闭。
⚠️ **需确认**:并行期预计多久?哪些业务需要回传 NC(仅应付,还是更多)?复核频率(每月?)?
