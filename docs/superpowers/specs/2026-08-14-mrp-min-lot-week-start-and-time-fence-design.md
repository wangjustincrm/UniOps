# MRP 最小生产批量 + 周起始日 + 锁定区设计（1B 修订，1C 前置）

- 日期：2026-08-14
- 状态：待评审
- 前置文档：`2026-08-03-mrp-subsystem-design.md`（V2.0 主设计）、`2026-08-07-mps-production-lead-time.md`、`2026-08-07-production-plan-matrix-design.md`、`2026-08-12-mrp-weekly-planning-and-intent-products-design.md`
- 代码基线：`origin/main` = `1460f48`（周排产已于 2026-08-14 上生产），mrp-api **318 passed**
- 影响阶段：修订已上线的 1B（MPS 排产）。**生产计划版本模型（下一轮 A）在本设计之后做** —— 先把排产结果算对，否则版本模型存下来的都是旧规则的计划

## 0. 为什么现在改

周排产上线后，业务侧确认了三件与现有实现冲突的事实：

1. **`min_output_qty` 的语义只实现了一半**。现在它只是"别把量摊得太薄"的软下限；业务真正的含义是**开一次工的最小经济批量** —— 某产品某周只要开工，就至少得产这么多，再少就是烧能源。而且这个数**每个产品不同**，现在只能设全厂一个值。
2. **工厂的周是周六到周五**。现有三种周模式里，两种 ISO 式的周起点硬编码为周一（`day - timedelta(days=day.weekday())`），第三种是每月 1/8/15/22/29 固定切分 —— **都排不出周六起算的周**，整个周网格与车间实际作业周错位。
3. **时界收敛为两段**（与生产确认后）：只要**锁定区**（原料已到，不能再改）和**自由区**（可随意调整），不做三段制的 Slushy 中间区。锁定区当前是 **3 个月**，需要做成设置项。

三项都动 1B 的排产引擎与设置，且第 1 项决定发布给 1C 的 `mrp_demands` 数量口径（按实际产量而非净需求），所以在 1C 开工前完成。

## 2. 最小生产批量

### 2.1 统一约束

> **约束 G**：任一「产品 × 周」格子的产量，**要么是 0，要么 ≥ 该产品的最小批量 L**。

现有 `_spread_ceiling`（"别摊太薄"）与本次新增的"开工下限"是同一件事的两面，合成这一条，**不保留两套语义**。

### 2.2 产品级最小批量：复用现有规则表，不建新表

`mrp_capacity_rules` 的 `scope_type` 本就预留了 `factory|product_family|line`，`scope_ref` 可存标识 —— **不需要迁移**。

- 新增 `scope_type='product'` + `scope_ref=<material_code>` + `constraint_type='min_output_qty'`。
- **解析顺序**：该产品自己的规则 → 全厂 `min_output_qty` → 无下限。
- 新增解析函数 `resolve_min_lots(db, week_start) -> dict[material_code, Decimal]`，只解析 `min_output_qty` 一种约束的 product 级规则并叠加全厂默认值。现有 `resolve_limits_for_week` 保持只管全厂三个约束，**不动**（它的 factory 级过滤是被分区唯一索引保护的，混进 product 级会破坏那层保证）。
- **写入校验（422）**：产品级最小批量必须 ≤ **规则生效期内当前有效的全厂 `max_output_qty`**（全厂未设上限则不校验）。否则这产品每次都凑不满一周、永远走到"往后排 + 报警"，规则本身就是错的。
- **引擎侧仍要兜底**：写入校验挡不住"先建规则、后调小全厂产能"和"某周产能例外把上限压到 L 以下"。引擎遇到 L 超过所有候选周产能时，走 §2.3 的产能优先例外（允许低于 L 并标 `below_min_lot`），**不能死循环搜索也不能静默丢需求**。
- **不快照进 run**：与现有产能规则一致 —— recalculate 的语义就是"按最新产能重算"。只有周模式、周起始日、lead、锁定区月数是快照项（见 §5.3）。

### 2.3 装箱（`q' ≥ L` 时）

- 可摊周数上限 = `floor(q' / L)`（现在这里读全厂值，改读产品自己的 L）；下限仍由产能决定 —— **产能永远赢**，现有口径不变。
- **紧张体制的尾槽必须回摊**：现在 `_pack_tight` 是逐周填满，`q'=90 / cap=40 / L=20` 会排出 `40+40+10`，尾巴那 10 违反约束 G。改为：尾槽不足 L 时，在该产品的周跨度内重新均分（`_level`）→ `30/30/30`。只要跨度 ≤ `floor(q'/L)`，均分后每槽必然 ≥ L。
- **★产能与约束 G 正面冲突时，产能赢**（沿用现有 `_spread_ceiling` 的既定口径，本设计不推翻）。`q'=21 / 周产能 20 / L=20`：一周装不下 21，摊两周就是 `10.5+10.5` 双双低于 L —— 此时**允许低于 L**，按 `10.5+10.5` 排，并在这两行标 `below_min_lot=True`（弱琥珀，tooltip 说明"周产能不足以在单周达到最小批量"）。**不**为了凑 G 把量顶到 `2×L=40`：那是凭空多产近一倍，比违反下限危害大得多。这是约束 G 唯一的例外，实现里必须有独立用例钉住。

### 2.4 顶批量与落位搜索（`0 < q' < L` 时）

顶到 L 的那一批**必须整批落在一个周**（拆开就又违反约束 G），按 E3 的顺序找：

1. **当月**（本 bucket）开放周里找剩余产能 ≥ L 的周，沿用现有 P1 连续 / P3 单品优先级；
2. 找不到 → **往前走**（复用现有 backward walk），逐周找剩余产能 ≥ L 的周，受现有保质期硬校验 `_placement_allowed`，底线仍是 `current_week`；
3. 还找不到 → **往后走**（新增能力，现在完全没有这条路径），逐周找到计划窗口末；命中即排，并标 `late_production=True`（晚于需求月 = 会缺货，琥珀报警）；
4. 整个窗口都塞不下 → 沿用现有 `capacity_gap`（红格），不静默丢需求。

### 2.5 超产结转

- 顶批量时 `surplus = L - q'`，记在该行的 `surplus_qty` 上，并累进引擎内的 `carry[material]`。
- 引擎已**按 bucket（归属月）升序**推进；每个 bucket 开工前先抵扣：`q' = max(0, 净需求 - carry[m])`，`carry[m]` 同步扣减。
- 抵成 0 的（产品 × 需求月）**必须产出一条 `qty=0` 的 covered 行**（见 §4.1），否则计划员在矩阵里根本看不到这个月。
- 窗口末仍有剩余 `carry` = 期末余库，在发布摘要里报一句。

### 2.6 保质期：两套口径，写死不许混

| 场景 | 口径 |
| --- | --- |
| **提前生产**（把某月需求提到更早的周产） | 现有 `_placement_allowed` **硬校验，不放宽** |
| **顶批量多产的部分躺库** | 按 E4 **照顶，标警告**：估算 surplus 被后续月需求吃完需要几个月，超过 `shelf_life × (1 - 安全余量 1/3)` 就标 `surplus_expiry_risk=True`，**不拦** |

### 2.7 两个必须点破的连带影响

- **守恒守卫要改**。引擎现在有 `产出 + 缺口 == 输入` 的 `RuntimeError` 守卫（`pack_bucket returned less than it was given`）。顶批量后总产量天然大于总需求，这条守卫必须改成 **`产出 + 缺口 == 输入 + Σ超产`**，否则一顶就炸。
- **发布给 1C 的量是实际产量**。`confirm_release` 写 `mrp_demands` 时必须写**含超产的实际生产量**，不是净需求 —— 原料要按真实产量买。
- **锁定行不受约束 G 限制**：计划员手工锁定的产量，引擎不推翻（现有 preload 语义不变）。

## 3. 周起始日

### 3.1 设置项

- 新参数 `week_start_dow`，存已有的 `mrp_planning_params`（key-value，JSONB），值 `0..6`（0=周一 … 5=周六 … 6=周日），**默认 `0`**；本厂设 `5`。
- **只作用于两种 ISO 式周模式**（`iso_thursday` / `iso_first_day`）。`month_fixed` 按定义就是每月 1/8/15/22/29 起，与周起始日无关，**不受影响**。
- `week_calendar.py` 仍是**唯一**允许知道周定义差异的模块 —— 周起始日随 `mode` 一起进出该模块，不允许泄漏到引擎/API/导出层。

### 3.2 归属月判据泛化

`iso_thursday` 现在的规则是"跨月周归周四所在的月"。周一起算时周四正好是**这周的第 4 天**（过半判据）。泛化为：**看这周的第 4 天落在哪个月**（周六起算 → 周二）。不为非周一起点另开分支。

### 3.3 周标签

现在用 `isocalendar()` 的 ISO 周号 —— 那是周一制的，周起点改成周六后显示 ISO 周号会**指错周**。改为：一律显示日期区间（`08-15 Sat → 08-21 Fri`），**只有**周起点 = 周一时才附 ISO 周号。

### 3.4 ★改设置时平移产能例外

产能例外（检修周）按 `week_start` 日期存。周起点从周一改成周六，整个网格平移，**旧例外行不再对上任何一周 → 检修周会静默失效**。

- `PUT /params/week_start_dow` 在**同一事务**内把 `mrp_capacity_exceptions.week_start` 平移到新网格上包含原日期的那个周起点，响应里返回"平移了 N 条"。
- 平移后可能撞唯一约束（两条旧例外落进同一新周）：**合并前先检测，冲突则整个请求 409 并列出冲突的周**，由计划员先自行删改。绝不静默丢弃任何一条。

## 4. 存储与展示

### 4.1 ★covered 行：矩阵取数路径带来的必堵之洞

实测：Production Plan 矩阵**完全由 lines 构建**（`ProductionMatrix.tsx` 按 `(产品, 需求月)` 去重取行上的 `demand_forecast`/`opening_stock` 快照，Planned 汇总非 gap 行的 `qty`）。

于是：**被结转抵完的月份一条 line 都不会有 → 那个产品那个月在矩阵里整个消失**，计划员看到的是"这月没需求"，而不是"需求 5 吨已被上月超产覆盖"。

做法：引擎为被完全覆盖的（产品 × 需求月）产出一条 **`qty=0` 的 covered 行**，钉在该月目标周，带 `carry_in_qty` 与快照。矩阵因此显示 **Demand 5 / Available 15 / Planned 0**（灰化），tooltip `Covered by 2026-08 minimum-lot surplus`。发布时 `qty=0` 不写 `mrp_demands`；xlsx 导出同样处理。

### 4.2 Available 行口径

现在 Available 只显示 `opening_stock`（净需求那套月度滚动算出的期初库存）。超产结转后真实可用 = `opening_stock + carry_in`。

- 行上存 `carry_in_qty`，矩阵 Available 显示两者之和，tooltip 拆开来源（`incl. 15 t carried from 2026-08 minimum-lot surplus`）。
- 不改的话矩阵会出现 **Demand 5 / Available 0 / Planned 0** 这种自相矛盾的行。

### 4.3 计划格与徽章

- 计划格 tooltip：`Net requirement 5 t + 15 t minimum-lot surplus`。
- 颜色优先级沿用现有（gap 红 > 其余琥珀）：`late_production` 琥珀、`surplus_expiry_risk` 弱琥珀。
- **xlsx 导出同步**：`mps_export.py` 与前端矩阵是两套实现、注释里互相 mirror，口径必须一起改。
- 发布摘要新增两句：本次总超产 X 吨、窗口末未消化余库 Y 吨。

### 4.4 迁移 `mrp11`（纯增量，可对有存量数据的生产库跑）

| 表 | 新列 | 默认 |
| --- | --- | --- |
| `mrp_mps_lines` | `surplus_qty NUMERIC(18,3)` | `0` |
| `mrp_mps_lines` | `carry_in_qty NUMERIC(18,3)` | `0` |
| `mrp_mps_lines` | `late_production BOOLEAN` | `false` |
| `mrp_mps_lines` | `surplus_expiry_risk BOOLEAN` | `false` |
| `mrp_mps_lines` | `below_min_lot BOOLEAN` | `false` |
| `mrp_mps_runs` | `week_start_dow SMALLINT` | `0` |
| `mrp_mps_runs` | `frozen_months SMALLINT` | `3` |

存量 run 全部按 `week_start_dow=0` 回放，历史计划字节不变。`down_revision` 挂 `mrp10b`（先查 `alembic heads` 确认真实链尾）。

## 5. 锁定区（时界）

### 5.1 边界

- 设置项 `frozen_months`（`mrp_planning_params`，默认 **3**）。
- **从当月起，含当月**：`current_month` 到 `current_month + frozen_months - 1` 的所有周属于锁定区，归属月判定用 `owning_month`（与周网格一致，不另算日期）。
- `frozen_months = 0` → 全自由，**等价于现有行为**，作为回归锚点。

### 5.2 生成新计划时的行为

1. 取**当前生效计划**在锁定区内的行，**原样复制**进新 run（qty、锁定标记、超产/报警标记全部保留），并预占产能（等同现有 locked 行的 preload 与 ledger 记账）。
2. **锁定区内需求变了不改计划**（原料已到）：新预测在锁定区内的差额 —— 缺的量推到**自由区第一个可用周**（走 §2.4 的正常搜索，标 `late_production` 报警）；多的量作为 `carry` 结转进自由区（复用 §2.5）。
3. 自由区正常排。
4. **★照抄进来的锁定区行也会产生最小批量超产**，那份 `carry` 必须带过边界进自由区，否则自由区会重复生产同一批货。

`recalculate` 同理：锁定区不动。

### 5.3 「当前生效计划」的临时定义

生产计划版本模型（下一轮 A）尚未做，且现状是**多个 run 可以同时是 `released`**（发布新计划不会把前任置为 superseded）。

- 本轮临时定义：**最近一次 released 的 run**（按发布时间降序取一）。没有生效版（首次生成）→ 锁定区照常排。
- **A 做完后换成 Default run** —— 这一条写进 A 的实施计划，不能忘。

### 5.4 只读

- 矩阵里锁定区的列灰底 + 锁图标；Demand 行显示**新预测**、Planned 显示**照抄的旧计划**，差额一眼可见。
- 锁定区内的行禁止 Adjust：**后端 `adjust` 端点一并 422 拒绝**，不能只靠前端挡（现有 IDOR/授权教训）。

### 5.5 快照

`frozen_months` 与 `week_start_dow` 一样**快照进 run**（§4.4），`get`/`recalculate`/`adjust`/导出一律读 run 存的值，绝不读当前设置 —— 与现有 `week_calendar_mode`/`production_lead_weeks` 同待遇。

## 6. 测试

现基线：mrp-api **318 passed**。前端无测试框架（tsc + 人工），**动手前自己量 tsc 基线**，不照抄记忆里的数字。

### 6.1 回归锚点

**黄金用例必须原样成立**：A60 / B20 / C30 / D30，周产能 40，4 周 → `W1:A40, W2:A20+B20, W3:C30, W4:D30`。加入最小批量（L=20）后**答案不许变**。

### 6.2 新增用例

1. **只开一次工**：需求 5 t × 3 个月、L=20、产能充足 → M1 排 20 t（`surplus_qty=15`），M2/M3 产出 covered 行（`qty=0`，`carry_in_qty` 分别 15、10），窗口末余 5 t。
2. **三段搜索四态**：当月有空档 / 当月满→往前 / 前后都试→往后并标 `late_production` / 全窗口满→`capacity_gap`。
3. **尾槽回摊**：`q'=90, cap=40, L=20` → `30/30/30`，不出 `40/40/10`。
4. **产品级覆盖全厂**：同一 run 内两个产品各自的 L 生效；无产品规则的落回全厂值；两者都无 → 无下限（等价现有行为）。
5. **保质期两套口径**：提前生产照拦（现有用例不许松动）；超产躺库超期 → `surplus_expiry_risk=True` 且**不拦**。
6. **守恒**：`产出 + 缺口 == 输入 + Σ超产`。
7. **产能赢过下限**：`q'=21 / 周产能 20 / L=20` → `10.5+10.5` 且两行 `below_min_lot=True`，**不**顶到 40；另测「先建产品规则、后把全厂产能调到 L 以下」与「产能例外把某周压到 L 以下」两条兜底路径。
8. **周起始日**：`dow=5` 全套 —— 周边界、归属月（第 4 天判据）、跨月 `shift_weeks`、标签；存量 run（`dow=0`）回放字节不变。
9. **例外平移**：改 `week_start_dow` 平移检修周并返回条数；平移撞唯一约束 → 409 且列出冲突周，不静默丢。
10. **锁定区**：`frozen_months=3` 时锁定区行照抄且预占产能；锁定区内需求增加 → 差额落自由区首个可用周并报警；锁定区行 Adjust → 422；`frozen_months=0` 等价现有行为。

## 7. 上线注意

- 迁移 `mrp11` **纯增量**，无破坏性操作，不需要像 `mrp10b` 那样先 `pg_dump` 清空重来。
- 但 **`mrp-api` + `mrp-web` + `mrp11` 仍是一个原子发布**：新前端读 `surplus_qty`/`carry_in_qty` 等列，旧 API 给不出。
- **上生产后要人工做的两件事**：①按产品录最小批量规则（不录则落回全厂值，行为与现在一致，不会炸）；②把 `week_start_dow` 设成 5 并确认检修周平移结果。
