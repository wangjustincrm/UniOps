# Inventory — 浏览器点验清单

分支 `feature/mrp-inventory`（叠在 `feature/mrp-1c-prereqs` 上）。
入口：MRP 左侧栏新增 **Inventory**，在 Consignment Stock 下面。

本地 dev 已经带上这套代码（`uniops_mrp_api` / `uniops_mrp_frontend` / `uniops_mdm_api`
三个容器挂的都是这个 worktree），刷新即可。

## 先说三件你会先注意到的事

**1. 原奶（NC 分类 0101）在这个页面上完全看不到。** 27 个物料、包括
`CR0059 Pasteurized Milk`，库存和在途两边都不计。页面顶部有一行说明，
不是 bug。判定按 **NC 物料基本分类**，不是按编码前缀 —— `CR0059` 顶着
原料前缀却是 0101，前缀规则两头都会错。

**2. "预计到货"这一列现在是空的。** ERP 里 `PO_ORDER_B.DPLANARRVDATE`
4,890/4,890 行都有值，同步代码也写好了，但**还没跑过一次全量 NC 同步**，
所以 `po_line_items.planned_arrival_date` 目前是 0 行有值。见文末"已知缺口"。

**3. 列表是按供应商批次汇总的，不是一行一个 WMS lot。** 3,532 个 lot 汇成
877 个批次。行数变少不是漏数据 —— 每行都写着它含几个 lot，右上角两个数都给。

**4. 数字已经和 SQL 对过账了**，两轮共 32 项交叉核对全过（在途 87 行 / 71 物料 /
902,779；Aging 五档批次 62 / 5 / 4 / 37 / 93，lot 92 / 11 / 11 / 95 / 334）。
所以如果你看到的数字和下面对不上，那是真出问题了，值得报。

## A. Batches —— 按供应商批次的库存

进 Inventory，默认落在 **Batches** 标签，物料类别默认 **0102 Raw Ingredient**。

**WMS 内部 lot 号已经从所有列表里拿掉了**（2026-08-18 按你的要求）。而且不是单纯
删列 —— 是**按供应商批次汇总成一行**。原因：3,532 个 lot 里有 **2,143 个**在去掉
内部编号后和别的行长得一模一样，`CP0080` 一个供应商批次下就有 **192 个 lot**。
只删列会变成 192 行重复内容。汇总后全库 **877 行**，原料 **200 行**。

- [ ] **A1** 表格出数，右上角显示 `N batch(es) · M lot(s)` —— **两个数都给**，
      因为知道仓库里有 543 个 lot 的人，只看到 200 行会以为丢了数据。
- [ ] **A2** 搜索框输 `lactose`（物料名）、`CR0025`（编码）、一个**供应商批次号**，
      三种都该能搜到。**内部 lot 号仍然能搜**（从 Flux 界面复制过来的能命中），
      只是不显示 —— 搜不到比"搜到了但看不出为什么"更糟。
- [ ] **A3** 类别切到 **All classes** 数量变大；切到 **02 Packaging Material**，
      Shelf life 列大片显示 **no expiry** —— 包材不过期，这是对的。
      这里也是碰撞最狠的地方：找 `CP0080`，**应该只有一行**，Lots 列写着 192。
- [ ] **A4** 点表头 Material / Supplier batch / Qty / Expiry / Received 排序，再点反向。
- [ ] **A5** 翻到第 2 页再翻回第 1 页，**不该出现同一批次在两页都有**。
- [ ] **A6** 已过期的行有淡红底，Shelf life 显示 `N d past`；未过期显示 `N d left`。
- [ ] **A7** Expiry 后面偶尔有个小 **+**（全库 42 个）——
      悬停显示"这批的 lot 到期日不一致，显示的是最早的那个"。
      这个必须有：批次里日期不一样时，那个日期只描述了一部分数量。
- [ ] **A8** Status 列偶尔显示 **mixed**（全库 27 个）—— 这批里有的可用有的冻结。
      **不能**只挑一个显示，那会把"一半货被冻结"藏起来。
- [ ] **A9** Supplier batch 列偶尔显示灰色的 **no supplier batch**（92 个 lot 确实没有），
      不是空白 —— 空白会被读成渲染坏了。
- [ ] **A10** 底部 `1–25 of N · as of <日期>`。as of 是**服务端**算的日期。
- [ ] **A11**（2026-08-18 新增）Qty 后面跟着 **UOM**（KGM / PIECES / EA…），
      来自物料主数据。有 5 个物料主数据里没有单位，那里不显示。
- [ ] **A12**（新增）**Produced** 列 = 生产日期，可点表头排序。
      按它升序 = 最老的货在最前，这就是先进先出要看的顺序。
      跨生产日期的批次（29 个）同样带一个 `+`。
- [ ] **A13**（新增）**Quality** 列 = **仓库自己的质量状态**：
      `Release(放行)` / `Block(禁用)` / `Under Inspection(待检)` / `Mixed`。
      ★ 它和右边那个 Status **是两回事，必须都看**：
      全库有 **278 个批次在仓库里是 Release、但按效期已经过期**。
      只看一个说不清是"QA 扣了"还是"日历到了"，而这两种要找的人不一样。
      随手可验的例子：搜 `CR0025`，`04/20/2019` 那行是 `Block` + `expired`，
      `12/17/2024` 那行是 `Release` + `available`。
      同一批次内部 QA 状态不一致的（29 个）显示 `Mixed`。

## B. Aging —— 保质期预警

切到 **Aging** 标签。

- [ ] **B1** 五张卡片：Expired / Under 30 days / 30 to 60 / 60 to 180 / Over 180，
      默认选中 **Expired**。0102 类别下**大数字是批次数**：
      **62 / 5 / 4 / 37 / 93**，小字里是 lot 数 **92 / 11 / 11 / 95 / 334**。
- [ ] **B2** 逐个点五张卡片，下面的表跟着换，**表里的行数要和卡片上的大数字一致**。
      这是最值得点的一条，而且这轮又改了一次单位：卡片原来数 lot、表格现在列批次，
      不改的话卡片写 92、表里 62 行，谁也解释不了。现在两边都是批次。
- [ ] **B3** 五张卡片的批次数相加 = **201**，lot 数相加 = **543**
      （= 0102 类里有保质期的 lot 总数）。★ 批次数相加会比"总批次数 200"多 1，
      **这是对的**：有 1 个批次的 lot 跨了两个档，它在两个档里各算一次，
      每档只算落在该档的那部分数量。
- [ ] **B4** 类别切到 **02 Packaging Material**：五张卡片基本都是 0，
      下面出现灰底提示 **"N batch(es)（M lots，数量 X）没有保质期，不在任何档里
      —— 包装和硬件不过期"**。这一行必须有。
- [ ] **B5** Days 列：过期的是负数且红字，30 天内的是橙字。
- [ ] **B6** 表里同样有 Supplier batch / Lots 两列，**没有** WMS lot 号；
      并且同样带 Produced 和 Quality 两列、Qty 后面带单位。

## C. Materials —— 物料汇总（含在途）

切到 **Materials** 标签，类别切到 **All classes**。

- [ ] **C1** 一行一个物料：On hand / Available / On hold / Expired /
      Next expiry / On order / Arriving。
- [ ] **C2** 勾上 "Hide materials with no stock and nothing on order" 前后，
      总数应该变化。
- [ ] **C3** 找一个 **On order 不为 0** 的物料（全库有 **71** 个）。
      那个数字是**蓝色可点的**，后面括号写着几张 PO。点开：
      - 展开的表列出 PO 号、供应商、订购量、已收、**Still owed**、Expected
      - **Still owed 那一列加起来必须等于上面那个 On order 数字**
      - 建议直接看 `CP0115`：2 张 PO，合计 **299,291**
- [ ] **C4** Expected 那一列现在应该都是灰色的 **"not stated"** ——
      不是空白。空白在日期列里读起来像"没有"，而"从来没人告诉我们"是另一回事。
- [ ] **C5** 没有在途的物料，On order 显示 **0**（不是空白），Arriving 显示 `—`。
- [ ] **C6** 搜索框输一个物料名，应该能搜到。
- [ ] **C7** 搜 `CR0180` 或 `CR0010`（原奶）——**应该什么都搜不到**。

## D. 跨标签页 / 导航

      （第一个标签页的 key 是 `batches`，不再是 `lots`）；

- [ ] **D3** 多页签外壳里，Inventory 页签的图标是个箱子，标题是 "Inventory"。

## 已知缺口 / 需要你决定的事

**1. ⚠️ epms-api 的 dev 容器挂的是别的 worktree。**
实测 `uniops_epms_api` 挂 `C:/Project/uniops-payofficer/epms-api`，不是主
checkout 也不是我这个 worktree。所以：

- 我加的 `po_line_items.planned_arrival_date` 列**已经手工在 dev 库建好了**，
  Inventory 页面读的是数据库、不经过 epms-api，**功能不受影响**；
- 但**改好的 NC 同步跑不起来**，所以到货日期填不进去。
  要看到 Expected 那一列有值，需要先把 epms-api 的挂载指回来，再跑一次
  全量 NC 同步。要我处理这个挂载、还是你在别的会话里弄？

**2. ⚠️ dev 库的 mdm alembic 版本表停在 `0006`，而迁移目录到 `0016`。**
这是**既有的**环境不一致（快照恢复时版本表没跟上，`materials` 里 0008 才加
的列明明已经存在），不是这轮造成的。我**没有去 stamp**（那会掩盖真实漂移），
而是：迁移文件在**全新空库上从 0001 跑到 0017 验证通过**，dev 库这两列手工
建 + 回填。**上生产前这个不一致要单独查清楚**，否则 `alembic upgrade head`
会在生产上从 0007 开始重跑。

**3. 在途还没接进 1C 的净需求。** 1C 现在仍然按"在途 = 0"算采购建议。
这轮把数据源建好了，但改净需求口径会动到已发布的采购建议，我按 spec 留到
单独一轮。要现在就接说一声。

**4. 没做主动推送。** 你选的是"只在页面看"。Aging 要发邮件/进待办随时能加。

**5. ⛔ 库位（点开批次看它在哪些库位）—— 数据源没接，我也验证不了。**
我们的 WMS 镜像只同步了 `INV_LOT` + `INV_LOT_ATT`（批次级），**没有库位**。
库位在 `INV_LOT_LOC_ID`（含 `LOCATIONID` / `QCSTATUS`）——
这是我们 2026-08-03 自己调研过的表，当时记在设计文档附录 A 里，
写着"库位/FEFO 明细视图**需要时用**"，现在正是需要的时候。

问题是：**dev 环境里 WMS 的 Oracle 凭据是空的**（`WMS_HOST` / `WMS_USER` /
`WMS_SERVICE` 全空，示例文件里也是空值），镜像数据是生产快照带来的。
所以我写得出这个查询，但**跑不了、也验证不了列名**——附录只记了两个列名，
join 键和数量列名都还是未知。**我不打算把一段没跑过的 Oracle 查询塞进生产同步路径。**

两条路，你选一条：
- **(a) 在 dev 里给上 WMS 只读凭据** —— 我像查 NC 那样先 survey 一遍
  `INV_LOT_LOC_ID` 的真实列，再动手。这条最稳。
- **(b) 按附录盲写，但做成"读不到就降级"** —— 库位读失败只记日志、
  批次同步照常，界面显示"库位数据不可用"。第一次生产同步时才真正验证。

**入库日期暂时留在汇总行没动** —— 你说它该跟着库位展开走，但展开还不存在，
现在挪走等于直接丢掉这个信息。库位一接上就一起搬过去。
