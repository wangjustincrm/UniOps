# 热修 `8e64eaa` — WMS 同步锁被漏在连接上，页面永远显示「正在同步」

`b1bae74`（本日已部署）带着一个 bug：Inventory 页点 Refresh 之后，按钮永远转圈显示
**“Syncing from WMS…”**，之后每次 Refresh 都拿到 409。

## 症状与影响

- **界面**：Inventory 页时效条一直显示 “Syncing from WMS…”，Refresh 点不动。
- **数据**：仍在同步，但**会变稀** —— 只有恰好落在攥着锁那条连接上的 tick 才拿得到锁。
  最坏情况是长时间不同步，而页面还在说「正在同步」。
- **不受影响**：NC 采购同步、换人自动 resync，以及 `b1bae74` 的其余部分。

## 根因

同步锁用的是 Postgres advisory lock，**它属于「连接」**。而代码是通过 SQLAlchemy
Session 加锁和解锁的，Session **不保证** 在 `run_wms_sync` 中途 `commit()` 前后还用同一条
连接。在运行中的服务上加探针打返回值，一次点击就抓到：

```
PROBE lock:   pid=46080 got=True
PROBE unlock: pid=46254 released=False   (locked on pid=46080)
```

`pg_advisory_unlock` 在没持锁的连接上执行只会返回 `false` —— 不抛异常、不写日志 ——
原来那条连接就一直攥着锁直到它被回收。`is_sync_running()` 于是永远回答「正在同步」。

★ 宿主上的单元测试全绿，而且**无法复现**：测试里连接池只有一条连接，Session 提交后拿回
的还是同一条，解锁自然打得中。这类问题只有真实链路（多连接竞争）才暴露得出来。

## 修法

改用**事务级** `pg_try_advisory_xact_lock`：Postgres 在事务结束时释放它 —— 提交、回滚、
连接断开都算。代码里不再有会打偏的解锁语句，进程被 kill 也不会留下孤锁。要保护的临界区
（删表 + 重灌镜像）本来就正好是一个事务。

新增 `mrp-api/tests/test_wms_sync_lock.py`：第一个用例**在旧实现上是失败的**，钉住的性质是
「锁随工作结束而结束」。

## 部署

**没有新迁移** —— `mrp16` / `ai01` 在 `b1bae74` 那次已经跑过。**不用跑 `migrate-prod.sh`。**

```bash
cd /opt/uniops
sudo git pull origin main
sudo sed -i "s/^TAG=.*/TAG=8e64eaa/" .env && grep '^TAG=' .env
sudo docker compose -f docker-compose.prod.yml pull
sudo docker compose -f docker-compose.prod.yml --profile edge up -d
```

只有 `mrp-api` 的代码变了，实际重建的容器就它一个（其余镜像 digest 未变）。
七个前端镜像与 `b1bae74` **逐字节相同**，指纹不变（portal `index-BXr9t5Ya.js`、
mrp `index-DDsipGCD.js`），**这是预期，不是没部署上**。

### 如果等不及热修，先止血

```bash
sudo docker compose -f docker-compose.prod.yml restart mrp-api
```

重启关掉它所有的数据库连接，被攥住的锁随之释放，页面立刻恢复。但只要还跑 `b1bae74`，
下次同步仍可能再漏一把。

## 部署后验证

```bash
DB_HOST=$(grep -m1 '^DB_HOST=' .env | sed 's/^DB_HOST=//; s/[[:space:]]*#.*$//')
DB_PASSWORD=$(grep -m1 '^DB_PASSWORD=' .env | sed 's/^DB_PASSWORD=//; s/[[:space:]]*#.*$//')

# ① 同步跑完后,持锁数必须是 0(修复前这里恒为 1,且 state=idle)
sudo docker run --rm --network host -e PGPASSWORD="$DB_PASSWORD" postgres:16 \
  psql -h "$DB_HOST" -U epms -d epms -c \
  "select pid, state from pg_locks join pg_stat_activity using (pid)
   where locktype='advisory' and ((classid::bigint<<32)|objid::bigint)=6290775923391811139;"

# ② 数据在往前走(隔 5 分钟查两次,last_success_at 应该变)
sudo docker run --rm --network host -e PGPASSWORD="$DB_PASSWORD" postgres:16 \
  psql -h "$DB_HOST" -U epms -d epms -c \
  "select source,status,row_count,last_synced_at,last_success_at from mrp_sync_state;"
```

界面上：Inventory 页应显示 “WMS data 刚刚 / N min ago”，Refresh 可点、点完出 toast。
