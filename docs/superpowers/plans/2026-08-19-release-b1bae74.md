## 上线后会自己变的三件事（先知道，别当故障）

1. **WMS 库存镜像开始每 5 分钟自动同步**（原来只能手动调接口，界面上连按钮都没有）。
   不想要就去 Portal → Admin → WMS Sync 把间隔设成 0。
2. **NC65 采购单/收货开始每小时自动增量同步**（原来纯手动）。同样，Admin → NC Purchase Sync
   设成 0 即关闭。自动运行**只跑 incremental**，Full reload 仍然只能手动 + 打确认字。
3. **改主角色 / 改用户部门 / 改审批路由之后，在途审批任务会自动改派**，不用再手动跑脚本。
   `PUT /authz/users/{id}/roles` 的响应从 204 变成 200 + `{"routing_resync": ...}`。

## 在应用服务器上（`10.10.50.65`，全程 sudo）

### 1. 拉代码

```bash
cd /opt/uniops
sudo git pull origin main
git log --oneline -3        # 应看到 b1bae74 这两个 merge
```

### 2. 备份数据库

生产库不在这台机器上（`DB_HOST=10.10.50.20`），prod compose 里没有 postgres 服务，
只能用一次性容器：

```bash
DB_HOST=$(grep -m1 '^DB_HOST=' .env | sed 's/^DB_HOST=//; s/[[:space:]]*#.*$//')
DB_PASSWORD=$(grep -m1 '^DB_PASSWORD=' .env | sed 's/^DB_PASSWORD=//; s/[[:space:]]*#.*$//')
sudo docker run --rm --network host -e PGPASSWORD="$DB_PASSWORD" postgres:16 \
  pg_dump -h "$DB_HOST" -U epms -d epms | gzip > ~/bk-$(date +%F-%H%M).sql.gz
gzip -t ~/bk-*.sql.gz && echo BACKUP_OK
```

`pg_dump` 失败时 `gzip` 照样产出一个看着正常的小文件，所以 `gzip -t` 那句别省。

### 3. ⛔ 前置检查：两张 alembic 表的当前值

```bash
sudo docker run --rm --network host -e PGPASSWORD="$DB_PASSWORD" postgres:16 \
  psql -h "$DB_HOST" -U epms -d epms \
  -c "select * from alembic_version_mrp;" -c "select * from alembic_version;"
```

- `alembic_version_mrp` = **`mrp15_wms_lot_uom`**、`alembic_version`（epms）=
  **`ah01_po_line_planned_arrival`** → 正常，继续。
- 任一不是上面的值 → **停下来别跑迁移**，把结果发我。这两个正是上一次发布 `d2dceb6`
  应该留下的位置；对不上说明上次没跑完或跑了别的。

### 4. 改 TAG 并拉镜像

```bash
sudo sed -i "s/^TAG=.*/TAG=b1bae74/" .env
grep '^TAG=' .env
sudo docker compose -f docker-compose.prod.yml pull    # ★ pull 千万别带 --profile edge
```

### 5. 先迁移，再起容器（顺序是硬约束）

```bash
sudo ./migrate-prod.sh
```

新版 mrp-api 的 `/admin/wms-sync/status` 会直接 SELECT `mrp_sync_state.last_success_at`，
新版 epms-api 的 NC 同步状态会 SELECT `company_config.nc_purchase_sync_interval_minutes`。
先换代码后迁移 = 这两个端点在中间窗口 500。

### 6. 起容器

```bash

sudo docker compose -f docker-compose.prod.yml ps
```

## 部署后验证

**① identity-api 必须活着**（这次它新增了 `httpx` 依赖，是本次风险最高的一处）：

```bash
sudo docker compose -f docker-compose.prod.yml logs --tail=30 identity-api
curl -sS -o /dev/null -w "%{http_code}\n" https://identity-api.canadaroyalmilk.com/health
```

看到 `ModuleNotFoundError: httpx` 就是镜像拉错了（应为 `:b1bae74`），立刻回滚。
identity 起不来 = 全员登录瘫，这一步别跳。

**② 前端指纹**（浏览器不用打开就能自证跑的是这枚镜像）：

```bash
curl -s https://portal.canadaroyalmilk.com/ | grep -o 'assets/index-[A-Za-z0-9_-]*\.js'
curl -s https://mrp.canadaroyalmilk.com/    | grep -o 'assets/index-[A-Za-z0-9_-]*\.js'
```

| | 期望 | 上一版 |
|---|---|---|
| portal | `index-BXr9t5Ya.js` | `index-Br5LMIIn.js` |
| mrp | `index-DDsipGCD.js` | `index-Dh8lNixr.js` |

epms / oa / finance / vms / booking 五个前端**镜像内容未变**，指纹与上一版相同，
这是预期的（本次没改它们）。

**③ WMS 调度真的在跑**（5 分钟内应看到时间往前走）：

```bash
sudo docker run --rm --network host -e PGPASSWORD="$DB_PASSWORD" postgres:16 \
  psql -h "$DB_HOST" -U epms -d epms \
  -c "select source, status, row_count, last_synced_at, last_success_at from mrp_sync_state;"
```

- `status='success'` 且 `last_success_at` 是刚才 → 正常。
- `status='failed'` + `last_error` 里是 Oracle 报错 → WMS 连不上，看 `.env` 的 `WMS_*`。
- 表里一行都没有、或 `last_success_at` 一直是空 → 调度没起来，看 mrp-api 日志。

界面上同样看得到：Portal → Admin → **WMS Sync**（新增区块），以及 MRP → Inventory
标题旁的时效条。

**④ NC 调度**：一小时内会自己跑一次增量。想立刻看，就去 Admin → NC Purchase Sync
把 `Sync every` 存一个值（存完下次 tick 就按新间隔算），或者直接点 Start Sync。
