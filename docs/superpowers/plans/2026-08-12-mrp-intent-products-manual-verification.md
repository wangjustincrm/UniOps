# 意向产品 · 手工验收清单

本特性的前端**没有任何自动化测试**（mrp/epms/portal/oa 四个前端都没有测试框架），后端逻辑有 21 条测试守着，但浏览器行为只能人工确认。以下清单由最终全分支评审产出，按依赖顺序排列。

分支：`feature/mrp-weekly-planning`（`b663821..85f9c4f`）
迁移：`mrp09_intent_products`（纯增量，可对有存量预测数据的生产库跑）

## 基础链路

1. **Sales Forecast → Add intent product**，填名称 + 备注 → Create。确认：整行琥珀底色、行首 `Intent` 徽章、**行名显示你填的名称而不是 `INTENT-` 占位码**、光标自动落在本月列。
2. **在该行录几个月的数字**，等 "Saved" → **刷新页面** → 数字还在、行还在、徽章还在。
3. **再建一个意向产品，什么都不输 → 刷新页面** → 该行**必须仍然在**（它由意向产品注册表而不是预测表决定是否存在）。这是合并前修掉的那个洞，专门验它。
4. 在意向行上试 **Excel 区块粘贴**（选中一格 Ctrl+V 一列数字）；再试**整表粘贴**（带产品码列）——意向码会被判为 unknown product code 跳过，这是既有行为，确认不报错不崩。
5. **KG / Tonne 来回切**，确认意向行数字随之换算、切换不丢未保存的编辑。

## 快照与排产

6. **Generate Outlook** → 弹窗顶部出现 "The grid has N intent product(s)…" 琥珀横幅；生成后在 Outlooks 面板 View，确认意向行在快照里看得到。
7. **Production Plan → 选该 outlook → Generate**。确认：计划矩阵里**没有**意向产品行；上方琥珀色 "N intent product(s) not scheduled this run"，**一个意向产品只列一条**（不是每月一条 = 18 条重复）；数量是该产品全部月份合计。
8. 对同一个 run 点 **Recalculate**，确认第 7 条的两个结论仍成立（重算路径最容易悄悄失效）。

## 绑定

9. 在意向行点 **Bind（链条图标）**。先故意在别的格子输一个数**不等保存**就去点 —— 确认图标是禁用的（颜色比可用时**更浅**），悬停提示在等自动保存。
10. 等保存完，点 Bind → 选一个**已经有预测数据**的物料码 → Confirm。确认弹出后端原文 `… already has forecast rows — merge them by hand first`，且大表数据**一格未动**。
11. 换一个**干净的**物料码 → Confirm。**弹窗开着的整个过程中试 Ctrl+Z、Ctrl+V、点格子** —— 全部必须无效（这是修了两轮才对的地方，最值得亲手验）。成功后确认：toast 报出移动的月数与吨数**并提示需要重新生成 outlook**；该行当场变成 `物料码 — 物料名`、琥珀底色消失、`Intent` 徽章消失（该物料无 BOM 则换成 `No BOM`）、数字一个不少留在原位。
12. **刷新页面**，确认第 11 步是服务端事实而非前端假象。
13. 点该行任意一格的**变更历史**，确认有一条 `intent_bind` 记录**且带操作人姓名**（不是空白）。
14. **重新 Generate Outlook** → Production Plan 用新 outlook 再跑 → 确认这个已绑定的产品**这次被排进计划**，琥珀横幅里不再有它。
    ⚠️ 拿**旧** outlook 跑它仍会被列为 skipped —— 这是设计如此（快照不可变），不是 bug。

## 回归与权限

15. **（`f4a0303` 回归）** Add Product 挑一个产品 → 立刻点该行 X → 确认不再崩（原症状：整个标签页白屏 + `Cannot read properties of undefined (reading 'id')`）。
16. 用**只有 `mrp.report.view`、没有 `mrp.demand.write`** 的账号打开 Sales Forecast：看得到意向行和徽章，但 "Add intent product" 按钮与 Bind 图标都不出现。

## 已知缺口（有意发布，非缺陷）

- **意向产品建好后无法从界面删除**。后端 `POST /api/v1/intent-products/{id}/drop` 已存在但前端没有调用方，所以建错名字的意向产品会一直显示。相比之前那个「点 X 会静默删掉已保存数据并让记录变成孤儿」的行为，这是安全的一侧。补一个 Drop 按钮是小跟进。
- **`GET /net-requirement` 不过滤意向行**，会对占位码算出净需求。今天没有消费者（MPS 在上游就挡掉了，也没有对应页面），但 **1C 的物料展开若从这里取数，意向产品会漏进采购建议** —— 1C 开工前必须处理。
- 绑定预览的吨数固定以吨显示、不跟随大表的 kg/t 开关；预览只统计已取回的月份区间（大表本来也只允许在该区间录数，所以与实际一致）。
